# Memo（文件记忆与上下文持久化）

> **Keep your context on disk.**

把进度写进文件，不靠聊天记录传递上下文。换会话、换 agent、对话太长截断，新接手的人读一个文件就能继续干活。

## 核心文件：MEMO.md

项目根目录下的 `MEMO.md` 是唯一的真相源。结构固定：

```markdown
# Memo — <项目名>

## 当前状态（YYYY-MM-DD 周X 更新）
- **正在做**：<一句话>
- **进度**：<做到哪了>

## 已完成（本轮会话）
- <条目>

## 下一步
1. <下一件事>

## 等用户
- <事项>

## 关键决策（不要随便改）
- <决策>：<为什么这么定>

## 环境/路径备忘
- 关键路径：<...>
- 特殊命令：<...>
```

## 工作流

### 1. 开始工作前：先读

进入项目后第一件事：

1. 看项目根有没有 `MEMO.md`。
2. 有 → 读一遍，恢复上下文。按"下一步"接着干。
3. 没有 → 问用户："要不要初始化 MEMO.md？"用户同意就创建空模板。

### 2. 工作中：关键节点更新

不是每句话都写文件，只在这些节点更新 `MEMO.md`：

- 完成了一个阶段性任务
- 做了一个重要决策（选了 A 不选 B）
- 遇到了一个卡点
- 用户给了新方向或改了需求

更新时改"当前状态"和"已完成"，不要重写整个文件。

### 3. 结束工作前：写档

对话要结束、用户要离开、或者上下文快满了，更新 `MEMO.md`：

- "当前状态"改成最新
- "已完成"追加本轮做完的事
- "下一步"写清楚接下来从哪继续
- "等用户"列出卡在用户动作上的事
- "关键决策"追加新决策

### 4. Git 集成（自动）

- 项目根有 `.git/` → 每次更新 MEMO.md 后自动 `git add MEMO.md && git commit -m "memo: <一句话摘要>"`。
- 没有 `.git/` 但用户说要版本管理 → 提示："要 git init 吗？"用户同意就 `git init`。
- 不要自动 push，本地 commit 就够。

## 硬约束

- **一个文件**：进度只写 `MEMO.md`，不要分散到多个文件。
- **不写废话**：MEMO.md 是给下一个接手的人看的，不是日记。每条都是可执行信息。
- **关键决策必记**：为什么选这个方案、放弃了什么，一句话说清。不然下次又纠结一遍。
- **不谎报**：没做完就写"做到哪了"，不要写"已完成"。
- **路径写绝对路径**：环境备忘里的路径复制粘贴就能用。
- **不覆盖历史决策**：关键决策段落只追加不删除，除非用户明确说改方向。
