# Baton（项目交接）

> **Pass the baton cleanly.**

项目告一段落、要换 agent、要交给同事时，说一声 baton，自动扫项目生成一份完整交接文档。接手的人看完就能干活，不用翻聊天记录。

## 工作流

### Step 1：扫项目

自动读项目根：
- `AGENTS.md` / `README.md` — 项目是什么、约束
- `MEMO.md` / `HANDOFF.md` — 当前状态（如果有）
- `tasks/active.md` / `tasks/backlog.md` / `tasks/done.md` — 任务看板
- `reviews/daily/最近几天.md` — 最近在干什么
- `goals/` — 当前目标
- `projects/` — 各子项目状态
- `git log --oneline -20` — 最近提交

### Step 2：生成 HANDOVER.md

项目根写 `HANDOVER.md`，结构固定：

```markdown
# HANDOVER — <项目名>

## 一句话项目说明
<这个项目是干嘛的、给谁用、当前状态>

## 怎么跑起来
- 环境要求：<Node/Go/Python/DB/...>
- 安装：<命令>
- 启动：<命令>
- 测试：<命令>
- 部署：<如果有>

## 当前状态（交接时）
- **做到哪了**：<一句话>
- **进行中**：<active.md 里的任务>
- **未完成**：<backlog 里跟接手相关的>

## 关键决策（别推翻）
- <决策>：<为什么这么定>
- <决策>：<为什么这么定>

## 坑和注意事项
- <踩过的坑>：<怎么绕>
- <特殊配置/账号/环境变量>

## 接手后第一件事
<下一个人打开项目应该先干什么>
```

### Step 3：Git 收尾

- 如果是 git 仓库：`git add -A && git commit -m "baton: handover doc"`
- 提示用户：交接前确认 HANDOVER.md 内容完整

## 硬约束

- **读文件，不编**：没读到的状态不写。
- **一份文档**：交接信息全在 HANDOVER.md，不分散。
- **写怎么跑**：接手的人第一反应是"这玩意儿怎么启动"，必须写清楚。
- **写关键决策**：接手的人最容易推翻前人决策，必须写清楚为什么。
- **不写废话**：HANDOVER.md 是给人快速上手的，不是项目历史。
