# Drill（深挖一个词到专家级）

把一个词/概念/领域，拆成一份**可执行的学习地图**：学什么、按什么顺序学、每步学到什么程度、去哪学、怎么检验学会了、哪里有坑。

不是讲知识本身（那是 formation-learning 的活），是给**学习路线图 + 权威资源 + 检验标准**。

## 工作流

按顺序执行，不要跳步。

### Step 1：定位这个词

先判断输入属于哪一类，不同类拆维度的方式不一样：

| 类别 | 例子 | 拆维度的角度 |
|---|---|---|
| 技术概念/工具 | 向量数据库、RAG、K8s、Rust | 核心概念 → 数据结构/原理 → 工程实现 → 性能调优 → 生态对比 → 适用/反适用 → 前沿 |
| 学科/理论 | 宏观经济学、演化心理学、分布式系统 | 历史脉络 → 核心公理/定律 → 主要流派 → 方法论 → 批判与反驳 → 现代应用 |
| 思想流派/哲学 | 斯多葛、道家、存在主义、AQAL | 历史与代表人物 → 核心主张 → 关键概念辨析 → 实践方法 → 批评者视角 → 现代解读 |
| 历史事件/现象 | 工业革命、2008 金融危机、文艺复兴 | 背景与起因 → 关键节点 → 主要人物/势力 → 直接后果 → 长期影响 → 当代回响 |
| 专业技能 | 系统设计、投资分析、GPT 提示工程 | 核心原则 → 方法论框架 → 常见场景套路 → 反模式 → 实战经验 → 进阶技巧 |

拿不准类别就问用户一句，但**不要罗列 5 个选项让他选**，直接给你判断的类别，他说不对再改。

### Step 2：联网搜权威资源（必做，不凭记忆）

这是 drill 跟 formation-learning 最大的区别——**资源必须真实存在、可点击**。

用 general_search 搜以下几类关键词（并行搜，不要一次一个）：

1. `<关键词> best books to learn` / `<关键词> 经典教材`
2. `<关键词> survey paper` / `<关键词> 综述论文`
3. `<关键词> official documentation` / `<关键词> 官方文档`
4. `<关键词> course tutorial` / `<关键词> 入门教程`
5. `<关键词> common pitfalls` / `<关键词> 常见误区` / `<关键词> mistakes`

**质量要求**：
- 每个资源必须有**可点击 URL**，不要只写书名不给链接。
- 优先一手源：官方文档、原论文、原作者博客、权威教材出版社页面。
- 二手解读可以给，但标注「二手解读」。
- **搜不到的资源就写"待核实"，不要凭记忆编一个书名或论文名凑数。**
- 每个维度给 1-2 个资源就够，不要堆 10 个链接让人选择困难。

### Step 3：拆 5-7 个专家维度

这个领域要真正懂透，必须覆盖哪几个维度？按 Step 1 的类别模板拆，实际数量 5-7 个，不要硬凑 10 个。

每个维度标注等级：
- **地基级**：不学这个后面全不懂
- **核心级**：工作/交流中天天用
- **进阶级**：专家和高级工程师的分水岭

### Step 4：每维度三层深度

对每个维度，写清楚三层：

```
维度名（等级：地基/核心/进阶）
├─ L1 入门（5 分钟能跟人聊两句）：这个维度的核心一句话是什么
├─ L2 进阶（能在实际场景中用起来）：要掌握哪些具体点
└─ L3 专家（能做决策/能辩论/能教别人）：要理解到什么深度
```

不要写散文，用要点。

### Step 5：学习路径顺序

用文字描述一条最短学习路径：
- 哪几个地基级维度必须先学（按什么顺序）
- 哪几个核心级维度可以并行
- 哪几个进阶级维度放到最后
- 给出一个"如果只给你 20 小时"的最短路径版本

### Step 6：自测检验点（场景判断题）

每个维度出 1-2 个**场景判断题**，不是背诵题。

好例子：
- ✅ "客户说'我们要做 RAG'，你怎么判断他到底需不需要向量数据库？什么情况下 Elasticsearch 就够了？"
- ❌ "什么是向量数据库？定义是什么？"（这是背诵）

### Step 7：资源地图

按维度组织，每个维度给：

| 资源类型 | 名称 | 链接 | 一手/二手 | 适合哪一层 |
|---|---|---|---|---|
| 官方文档 | XXX | https://... | 一手 | L1-L2 |
| 经典书 | 《XXX》作者 | 出版社/豆瓣链接 | 一手 | L2-L3 |
| 综述论文 | XXX | arxiv 链接 | 一手 | L3 |
| 入门视频 | XXX | B站/YouTube 链接 | 二手 | L1 |
| 动手项目 | XXX | GitHub 链接 | 一手 | L2 |

### Step 8：新手 3 个坑

这个领域新手最容易踩的 3 个误解/误区，每个一句话说清楚"为什么错"和"正确认知是什么"。

### Step 9：专家 vs 半吊子分水岭

一句话说清楚：真正在这个领域能做决策的人，和看过 10 篇博客的人，本质区别是什么。

```

| 维度 | 等级 | L1 入门 | L2 进阶 | L3 专家 |
|---|---|---|---|---|
| 维度1 | 地基 | ... | ... | ... |
| 维度2 | 核心 | ... | ... | ... |
| ... | | | | |

## 二、学习路径（最短顺序）

1. 先学：维度1 → 维度2（地基，必须串行）
2. 并行学：维度3 + 维度4
3. 最后碰：维度5（进阶）

**20 小时速成版**：[给一个最短路径]

- 维度1：<场景判断题>
- 维度2：<场景判断题>
- ...

[按维度分小节，每个维度列 1-2 个资源，带链接，标注一手/二手]

1. <坑>：为什么错 → 正确认知
2. ...
3. ...

## 六、专家 vs 半吊子分水岭

<一句话>

---
*资源来源说明：联网搜索 N 条，其中一手源 N 个，二手解读 N 个，待核实 N 个。*
```

## 硬约束

- **不编造资源**：书名/论文名/链接必须来自搜索结果，搜不到就标"待核实"，不要凭记忆凑数。
- **不做 ELI5 讲解**：不要把每个知识点都用大白话讲一遍——那是 formation-learning 的活。drill 只给路线和资源。
- **不罗列 10 个资源让用户选**：每维度 1-2 个，给出推荐理由。
- **维度不超过 7 个**：多了用户看不完，少于 5 个说明没拆透。
- **路径要可执行**：不要说"深入理解一下"这种废话，要说"读完 X 章 → 跑通 Y 项目 → 能答出 Z 题"。
- **用户厌恶废话**：不要开头写"好的，我来帮你深入研究 XXX"，直接上结构。
- **场景判断题优先**：自测题不要考背诵，要考"遇到这个场景你怎么判断"。
