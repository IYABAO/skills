# 阵型学习法（Formation Learning）

## 这个技能是什么

把任何知识领域当作**一支足球队**来理解：知识点是球员，按职能排进 4-3-3、4-2-3-1 等阵型，
再配一个主教练（一句话核心思想）、一个门将（底线基础）和替补席（进阶知识点）。
每个"球员"都用 ELI5 的方式讲成大白话。最后交付：**阵型图（SVG）+ 球员卡 + 教练战术板**。

它内化了 ELI5 技能的内核，因此所有讲解遵循：

> **假设零背景，不是零智商（assume zero background, not zero intelligence）**
> - 用 5 岁小孩也能懂的大白话 + 日常类比，但不牺牲准确性。
> - 每个专业词第一次出现时，紧跟一句大白话解释。
> - 短句、短段、口语化；先讲"它是干嘛的"，再讲"怎么做到"，最后讲"为什么重要"。

## 工作流

按顺序执行：

1. **摸清主题与范围**：读全用户输入（含附件）。明确"要学的到底是什么"、边界在哪。
   如需外部事实，先检索/读资料，确保知识点有来源、不编造；拿不准的标"待考证"。
2. **盘点知识点**：列出该主题的**主流知识点**，每个先写好"一句大白话解释 + 一个日常类比"，
   并打上职能标签：地基(守)/机制(转)/思想(想)/应用(打)/结论(进)。
3. **数人数，定阵容**：按 `references/formations.md` 的人数规则：
   ≤ 20 个主流点 → 一套主力阵型（+替补席）；> 20 个 → 主力 + B 队。
   再按知识结构的形态选阵型（如均衡→4-3-3、单一主结论→4-2-3-1、双板块→4-4-2、机制厚→3-5-2）。
4. **排位置**：按 `references/positions.md` 的角色映射，把知识点放进对应位置：
   主教练 = 一句话核心思想；门将 = 最底层基础；CB = 核心基础；LB/RB = 背景前置；
   CDM = 机制；CM = 方法/流程；AMD(CAM) = 核心思想/理论；LW/RW = 应用/案例；
   CF = 核心结论；SS = 衍生结论；替补 = 进阶/边角。**人不够 11 个就留空位**（= 可继续深挖的位置）。
5. **写球员卡**：每个首发球员按下方【球员卡模板】用 ELI5 写法输出；替补/B 队可更简。
6. **画战术板**：写出学习路径（球路，如 GK→CB→CDM→AMD→CF）、关键连线（谁和谁强相关）、
   以及"三种输球方式"（最容易误解/出错的点）。
7. **渲染阵型图**：把阵容写成 JSON，运行 `scripts/formation_diagram.py` 生成 SVG（见下）。
8. **交付**：按【输出模板】组织正文，阵型图用 present_files 交付，正文给出完整球员卡与战术板。

## 输出模板

按此结构组织最终回答（阵型图作为配图放在最前面）：

```
# 【主题】阵型学习卡（阵型：XXX）

## 主教练的话
[一段 ELI5 大白话总览 + 主教练=一句话核心思想]

## 阵型图
[SVG]

## 首发阵容
### 门将 GK
- 【知识点名】一句话大白话
### 后卫（CB / LB / RB）
- ...
### 中场（CDM / CM / AMD）
- ...
### 前锋（CF / SS / LW / RW）
- ...

## 替补席
- ...

## 教练战术板
- 为什么用这个阵型：一句话
- 球路（学习路径）：GK → CB → CDM → AMD → CF ...
- 关键连线：A 和 B 的关系一句话
- 三种输球方式（最容易错/误解的点）：3 条

## B 队（如果适用）
[B 队阵型、B 队教练=次级核心思想、球员卡精简版]
```

## 球员卡模板（ELI5）

每个首发球员卡统一 4 行（默认 1–3 句；用户要求"深入"时可扩到 100–300 字）：

```
【位置代码｜知识点名】
- 是什么：一句大白话（像对 5 岁小孩解释）
- 像什么：一个日常类比（玩具/厨房/上学/手机……）
- 传给谁：它和哪些队友联动（依赖/关系）
- 为什么在这：一句话说明它为什么待在这个位置
```

## 渲染阵型图

1. 把阵容写成 JSON（结构见脚本 docstring）：
   - `topic` 主题名；`formation` 阵型；`coach` 主教练；`players` 首发（含 pos 位置代码）；
   - `bench` 替补；`flow` 可选（学习路径箭头，按位置代码顺序）；`b_team` 可选（B 队整块）。
2. 运行：
   `python3 scripts/formation_diagram.py team.json output.svg`
3. 校验输出 SVG 存在且非空，然后交付。空位会自动画成虚线"?"圈（可继续深挖的位置）。

## 质量要求（交付前自查）

- [ ] 主教练能一句话统领全队（找不到就如实说明，不硬编）
- [ ] 每个首发球员都满足 ELI5：零背景可懂、有类比、无未解释的术语
- [ ] 位置分配符合 positions.md 的职能逻辑，不按重要性硬排
- [ ] 知识点数量 > 20 时启用了 B 队；≤ 20 时没有强行凑满 11 人
- [ ] 知识点来自用户输入或已核实的来源，不编造；不确定的标"待考证"
- [ ] 阵型图已生成、已交付，正文结构与输出模板一致
- [ ] 用户要求深入时，关键球员卡有足够细节而不是只有一句话
