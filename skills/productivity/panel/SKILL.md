# Panel（多角色方案评审）

> **Stress-test your plan from every angle before you commit.**

你有一个方案，自己看总是觉得没问题。这个 skill 让你在动手前，先站在 3-4 个不同角色的立场上挑刺。

## 工作流

### Step 1：明确方案

先让用户说清楚：方案是什么、要解决什么问题、约束条件（时间/钱/人/技术栈）。模糊的方案审不出东西。

### Step 2：选角色（按方案类型选 3-4 个，不要全上）

| 角色 | 立场 | 问的问题 |
|---|---|---|
| **用户视角** | 这方案真解决我的痛点吗 | "如果我是用这个东西的人，我会满意吗？我会遇到什么不爽？" |
| **魔鬼代言人** | 专门找失败点 | "这方案最可能怎么死？哪里最脆弱？" |
| **技术现实派** | 可行性/成本/时间 | "真做出来要多久？要多少人力？有什么技术债？" |
| **未来视角** | 半年后回看 | "半年后这方案会变成什么样？会不会要推翻重做？" |
| **利益相关方** | 谁会受影响 | "这方案对老板/同事/客户有什么影响？谁会反对？" |

### Step 3：逐角色输出

每个角色一段，格式固定：

```
### <角色名>
- **最大的问题**：<一句话>
- **具体说**：<这个角色看到的 1-2 个具体风险/漏洞>
```

不要和稀泥。每个角色必须说出至少一个真问题，说"挺好的没意见"就是失职。

### Step 4：汇总结论

最后输出：
- **必须改的**：真问题，不改会出事
- **可以讨论的**：有争议但不是致命
- **可以忽略的**：角色提了但其实不重要（说清楚为什么忽略）
- **结论**：方案能走，还是要大改

## 硬约束

- **每个角色必须挑刺**：不允许"这个方案很完美"。
- **不替用户做决定**：只把问题摆出来，改不改用户定。
- **不重复**：3-4 个角色提的问题不能是同一个点换个说法。
- **具体不抽象**：不要"可能有风险"，要"如果 X 发生，Y 会崩"。
- **按方案类型选角色**：个人决策不用上"利益相关方"，技术方案不用上"用户视角"。
